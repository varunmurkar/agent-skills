# Review Comment Style

Use one actionable finding per line:

`path:line: severity: problem. fix.`

- Keep exact file, line, symbol, and relevant error names.
- Use `bug`, `risk`, `nit`, or `question` when severity or intent matters.
- State why when the fix is not obvious.
- Do not restate the diff, hedge, or add per-finding praise.
- Explain security and architectural findings fully instead of compressing them.
